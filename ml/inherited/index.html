crop_recommendation.py
ml/algorithms/crop_recommendation.py
Inference Algorithm 53 lines

Provides real-time agronomic crop recommendation through two distinct pathways: (1) chemical soil test (N, P, K) combined with meteorological inputs across 51 crops, and (2) visual soil type string combined with weather across 31 crops. Also ranks top-3 alternative crops by probability.

Function Signatures & Contracts
FunctionInputsReturn Value
recommend_crop() N, P, K float (mg/kg)
temperature float (°C)
humidity float (%)
ph float (0-14)
rainfall float (mm) 		dict:
- recommended_crop: str
- confidence: float (0-1)
- alternatives: list[dict]
recommend_crop_from_soil_type() soil_type str
temperature, humidity, ph, rainfall float 		dict:
Same structure as above; uses 31-crop model with OneHotEncoded soil type.
Step-by-Step Low-Level Mechanics
1
Base Path Resolution: Dynamically derives BASE_DIR using os.path.dirname(os.path.abspath(__file__)) to prevent broken relative imports when executed from external backend endpoints.
2
Joblib Deserialization: Loads crop_recommendation_model.pkl and crop_soil_type_model.pkl into memory at module load time. Unpacks the estimator alongside original training feature names.
3
DataFrame Row Construction: Formats input arguments into a single-row Pandas DataFrame matching exact expected column ordering to avoid scikit-learn feature name mismatch warnings.
4
Probability Ranking: Calls predict_proba(), zips classes with probabilities, sorts descending, and returns the top class plus ranks 2 through 4 as alternative recommendations.
Algorithmic Nuance: Multi-Model Separation
Why two separate models instead of one? A farmer with laboratory N-P-K soil test results should not be constrained by broad textural categories (like "Alluvial" or "Clay loam"). Conversely, a farmer without a soil lab test only knows their physical soil type and regional weather. Separating these into crop_recommendation_model.pkl (51 crops, 6,596 rows) and crop_soil_type_model.pkl (31 crops, 3,100 rows) provides maximum utility for both user personas without synthetic data contamination.

disease_info_retrieval.py
ml/algorithms/disease_info_retrieval.py
Inference Algorithm NLP Retrieval 55 lines

Multilingual Information Retrieval (IR) engine for plant pathology. Given a farmer's free-text natural language symptom description in English, Hindi, or Marathi, it computes vector cosine similarity against 2,231 verified diagnostic Q&A pairs and returns the diagnosis and remedy.

Function Specification
ParameterTypeDescription
querystrFarmer's raw complaint (e.g. "upper leaves yellow drying maize") in EN, HI, or MR.
top_kint (default 3)Maximum number of relevant remedies to retrieve.
Returnsdict{"matches": [...]} with similarity, matched question, crop, disease, severity, and remedies in 3 languages.
Low-Level Search Algorithm
1
Vectorization: Projects query string into the 5,000-feature unigram+bigram TF-IDF space via _vectorizer.transform([query]).
2
Cosine Similarity: Calculates dot product normalized by L2-norm against precomputed _tfidf_matrix, producing a similarity vector in range [0, 1].
3
Threshold Filtering: Rejects candidate matches scoring below LOW_CONFIDENCE_THRESHOLD = 0.15 to avoid hallucinating remedies on irrelevant questions.
4
Source Metadata Hydration: Maps matrix index back to original CSV row via row_idx to fetch multilingual remedy strings.
⚠️
Confidence Guardrail: If the cosine similarity score is below 0.15, the system explicitly returns "No close match found in the knowledge base" rather than guessing. Agricultural remedies (e.g. chemical fungicides) can destroy crops if prescribed erroneously.

ml/algorithms/disease_prediction.py
Inference Algorithm 61 lines

Image-based plant disease classification using classical computer vision features (HSV color histograms and local variance texture) with a Random Forest classifier over 26 PlantDoc classes. Serves as a CPU-compatible baseline with a warning regarding CNN superiority.

Feature Extraction Mechanics (44 dimensions)
1
Color Normalization: Reads image via PIL, converts to RGB, resizes to 96x96 pixels, and scales values to [0.0, 1.0].
2
HSV Histogram (36 feats): Converts to HSV color space and computes 12-bin normalized histograms independently for Hue, Saturation, and Value channels.
3
Texture Variance (2 feats): Converts to grayscale and runs scipy.ndimage.generic_filter with a 5x5 window calculating local pixel variance; extracts mean and standard deviation of texture roughness.
4
RGB Channel Moments (6 feats): Appends mean and standard deviation across R, G, and B color channels.
I/O Contract
FieldTypeNotes
image_pathstrLocal absolute path to jpg/png leaf image.
predicted_classstrOne of 26 PlantDoc disease categories.
confidencefloatPredicted probability (0.0 to 1.0).
top_3list[dict]Top 3 classes with corresponding confidence.
warningstrExplains the 18.6% classical CV accuracy ceiling.
⚠️
Architectural Reality: This model achieves ~18.6% accuracy because plant pathology involves micro-lesions, ring spots, and necrotic edges that color histograms cannot resolve. This script provides the standard backend interface so that swapping in disease_cnn_model.keras requires zero API changes.

Inference Algorithm 44 lines

Field checklist diagnostic tool for extension workers. Evaluates a dictionary of binary "Yes"/"No" answers against a trained Scikit-Learn Decision Tree (max depth 5) to predict Early Blight disease presence.

Input/Output Protocol
FieldFormatDescription
answersdict[str, str]Mapping of question string to "Yes" or "No".

Critical Checklist Trap & Mechanics
The function maps 1 if answers.get(q) == "Yes" else 0 for each of the 30 recognized questions in _features.

The Partial Checklist Trap: If an officer only answers 3 questions as "Yes" and leaves 27 blank, those 27 default to 0 ("No"). The decision tree path requires a combination of co-occurring symptoms; 27 negative answers will override the 3 positive symptoms and falsely classify as "Not Present". The caller UI must ensure all 30 questions are completed.

TensorFlow/Keras Convolutional Neural Network trained from scratch for leaf disease classification over PlantDoc. Includes data augmentation layers (random flip and rotation), convolutional feature extraction blocks, and smoke-testing capability.

Neural Network Architecture
1
Input: (96, 96, 3) RGB images rescaled by 1.0 / 255.
2
Augmentation: RandomFlip("horizontal") + RandomRotation(0.1).
3
Conv Layers: 3 blocks of Conv2D(filters, 3, activation="relu", padding="same") with 32, 64, and 128 filters, each followed by MaxPooling2D().

Exclusion: Excludes "Tomato two spotted spider mites leaf" (only 2 training images in dataset).

Lookup Builder 44 lines

Extracts deterministic nutritional requirements per crop from Fertilizer.csv. Groups by crop to extract constant optimal N, P, and K targets along with minimum and maximum acceptable pH ranges into a clean JSON table.

Extraction Logic
1
Reads datasets/Fertilizer.csv and groups rows by "Crop".
2
Extracts N, P, and K values (which are constant per crop).
3
Computes ph_min = group["pH"].min() and ph_max = group["pH"].max().
4
Writes structured JSON lookup to saved_models/fertilizer_targets.json.
Why a Lookup Table Instead of ML?
In the raw data, N, P, and K values for a given crop are constant across all entries (e.g. Rice is always N=80, P=40, K=40). Training a regression model would simply memorize a static key-value mapping. Building a clean lookup table avoids unnecessary model overhead while serving the deficit calculation directly.
