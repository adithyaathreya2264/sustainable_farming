User Goals Inventory

✓Securely access the platform without remembering passwords.
✓Establish a digital baseline of the farm (Fields and Soil).
✓Track active growing seasons (Crop Cycles).
✓Log day-to-day farm activities (chemicals, water, labor, expenses) reliably, regardless of internet connectivity.
✓Receive, understand, and act upon predictive agronomic alerts.
✓Discover and pursue eligible government agricultural subsidies.
✓Ensure all inputted data is safely backed up to the cloud without manual effort.

Detailed User Workflows

WF-01
Authentication & Onboarding

Purpose: Securely authenticate the user using a frictionless passwordless method.

Requirements: FR1.1 Trigger: App opened for the first time or after logout Preconditions: Valid phone number, cellular reception
Main Flow (Happy Path)
  1. User enters their 10-digit mobile number.
  2. System requests OTP from SMS Gateway.
  3. System displays the OTP entry state.
  4. User receives SMS and inputs the 6-digit OTP.
  5. System validates the OTP.
  6. System issues a persistent local authentication token.
  7. System routes user to the Home Dashboard.
Decision Points
Is this a new or returning user? If new, prompt for basic profile name and preferred language before routing to Dashboard.
Alternative Flows
Auto-read OTP (if device OS allows, system auto-fills the OTP and proceeds to validation).
Exception Flows
E1No Network. System displays "No connection. Please connect to request OTP." (User must wait).
E2Invalid OTP. System displays "Incorrect code." User clears input and retries.
E3Max Retries Exceeded. System locks request for 5 minutes. Displays countdown timer.
Exit ConditionsSuccess (Authenticated), Failure (Cannot authenticate).
PostconditionsApp state is authenticated. Offline database is unlocked and ready for queries/writes.
WF-02
Field Mapping & Soil Initialization

Purpose: Define the geographic boundaries of a field to fetch automated soil baseline data.

Requirements: FR1.2 Trigger: "Add Field" action from the Fields Dashboard Preconditions: Authenticated; location services enabled (optional)
Main Flow (Happy Path)
  1. System requests location permission.
  2. User grants permission.
  3. System centres the map on the user's current GPS location.
  4. User drags the pin to the exact center of their field and confirms location.
  5. User inputs Field Name and Area Size (using local measurement units picker).
  6. System converts local units to standard metric in the background.
  7. System calls the external Regional Soil API using the pin coordinates.
  8. System saves Field parameters and fetched Soil Profile to the local database.
  9. System returns user to Fields Dashboard with success confirmation.
Decision Points
Location Permission Denied? Map centres on a default regional view; user must manually pan to their farm.
Exception Flows
E1API Failure / Offline. System cannot fetch Regional Soil data.
Recovery: System saves the Field Name, Area, and GPS coordinates locally. Flags the Field as requiresSoilSync = true. Returns user to Dashboard. System will fetch soil data silently in the background when connectivity returns.
Exit ConditionsField successfully created.
PostconditionsField entity exists in the database. Area is standardized to metric for future ML calculations.
WF-03
Initialize Crop Cycle (Planting)

Purpose: Anchor upcoming activities and ML predictions to a specific biological planting.

Requirements: FR2.1, Product Plan (Crop Cycle Tracking) Trigger: "Add Planting" for a specific Field Preconditions: At least one Field exists (WF-02 completed)
Main Flow (Happy Path)
  1. User selects the target Field.
  2. User selects the Crop Category (e.g., Wheat).
  3. User selects the specific Crop Variety from the Master Catalog.
  4. User selects Sowing Date (defaults to today).
  5. User confirms planting.
  6. System saves FieldPlanting record locally and flags for cloud sync.
Exception Flows
—Missing input (e.g., no variety selected). System disables the "Save" action until required selections are made.
Exit ConditionsCrop Cycle successfully initialized.
PostconditionsField status changes to "Active". ML engine begins tracking weather against this specific variety.
WF-04
Quick Log Intervention / Expense (Offline-First)

Purpose: Frictionlessly record daily farming activities (chemicals, labor, harvest) in any network condition.

Requirements: FR2.1, FR5.1, FR5.2, BR1 Trigger: Global "Quick Log" action Preconditions: At least one active Crop Cycle exists
Main Flow (Happy Path — Action Logging)
  1. User selects the target Field/Planting.
  2. User selects the Action Type (e.g., Chemical Application).
  3. System loads the local AgriInputCatalog.
  4. User selects the specific Product.
  5. User inputs the Quantity applied and selects the local Unit (e.g., Bags, Liters).
  6. User confirms the log.
  7. System applies unit conversion, saves FieldIntervention locally, and flags isSynced = false.
  8. System displays success confirmation and returns to previous screen.
Decision Points
Is this logging fulfilling a prior ML Recommendation? If the user logs a product that matches an active recommendation, the system links the intervention_id to the recommendation_id automatically behind the scenes (Closing the ML loop).
Alternative Flows
User selects "Labor Expense". System skips the Product Catalog and prompts for "Number of Workers" and "Total Wage Paid".
Exception Flows
E1Missing numerical quantity. System highlights the quantity field and requires input before saving.
Exit ConditionsActivity saved locally.
PostconditionsFarm operational ledger is updated. ML feedback loop is updated.
WF-05
View & Acknowledge Agronomic Alert

Purpose: Act upon AI-driven predictive insights regarding crop threats.

Requirements: FR3.1, FR3.2, FR4.1 Trigger: Push Notification tap or Alert Card selection on Home Dashboard Preconditions: ML engine has generated a Recommendation for an active planting
Main Flow
  1. System displays Alert Details (Threat type, Confidence, Affected Field).
  2. System displays the actionable Recommendation (Specific product and dosage).
  3. System queries mapping API and displays a list of nearby vendors carrying the product.
  4. User acknowledges the alert (Dismisses or selects "Log Action Now").
Alternative Flows
User selects "Log Action Now." System routes directly to WF-04 (Quick Log) with the Field, Action Type, and Product pre-filled.
Exception Flows
E1Offline while viewing vendor map. System hides the map module and displays a message: "Vendor map unavailable offline. Check back when connected." The alert details remain fully readable.
Exit ConditionsAlert acknowledged or acted upon.
PostconditionsRecommendation state changes if acted upon.
WF-06
View & Claim Government Scheme

Purpose: Inform the farmer of matched financial subsidies and provide claim instructions.

Requirements: FR6.1, FR6.2, FR6.3, FR6.4 Trigger: Scheme Notification selection from the Dashboard Preconditions: Backend ML/Rules engine has matched user parameters to scheme criteria
Main Flow
  1. System displays Scheme Details (Subsidy amount, purpose, deadline).
  2. System displays the exact matched criteria (e.g., "Matched because you own < 2 Hectares in Mysuru").
  3. System provides Claim Instructions (External link or local office phone number).
  4. User takes action externally (calls office/visits link).
  5. User marks the scheme as "Application Started" within the app.
Exit ConditionsScheme viewed and tracked.
PostconditionsScheme tracking status updated in the user's profile.
WF-07 — System Workflow
Background Data Synchronization

Purpose: Automatically upload offline data to the cloud without user intervention.

Requirements: FR2.2 Trigger: Device OS detects restoration of internet connectivity Preconditions: Local database contains records flagged isSynced = false
Main Flow
  1. System detects network stability.
  2. System aggregates all unsynced local records (Interventions, Harvests, New Fields).
  3. System dispatches a bulk mutation payload to the Cloud Database.
  4. Cloud Database acknowledges successful write.
  5. System updates local records to isSynced = true.
  6. System updates the UI global sync indicator to a "Success" state.
Exception Flows
E1Network drops during payload dispatch. System halts process. Records remain isSynced = false. System waits for next network restoration trigger.
E2Timestamp conflict (e.g., record modified on another device). Cloud Database rejects the specific conflicting record. System resolves conflict by prioritizing the most recent updated_at timestamp, overwrites local state, and marks as synced.
Exit ConditionsAll local data matches cloud data.
PostconditionsCloud analytics and ML engines can now process the newly uploaded data.

Cross-Workflow Review & UX Risks

Traceability Check

All functional requirements (FR1.x through FR6.x) are represented in the workflows.
The strict Offline-First mandate is inherently satisfied by routing all data creation (WF-02, WF-03, WF-04) strictly to the local database first, relying on WF-07 (System Sync) to handle cloud communication.

Identified UX Risks & Mitigations

Risk 1 — Data Stagnation
A farmer logs data offline (WF-04) but does not connect to the internet for three weeks. The ML engine cannot analyze the data or send alerts, defeating the product's value.
Mitigation: If isSynced = false persists for more than 48 hours, the UI should trigger a local notification urging the user to briefly connect to Wi-Fi/Cellular to secure their farm data.
Risk 2 — Duplicate Logging
The user receives an Alert (WF-05), clicks "Log Action Now," saves it, but later forgets and logs the same chemical spray manually via Quick Log (WF-04).
Mitigation: During the Quick Log workflow, if the system detects an identical product logged for the same field within a 24-hour window, it displays a warning: "This action was recently logged. Are you sure you want to duplicate it?"
