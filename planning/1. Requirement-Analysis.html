Requirements Specification

Sustainable Farming App

Date: July 2026 Phase: Requirement Gathering Completed
1

Problem Statement

Smallholder farmers often lack access to precise, localized agronomic advice and real-time economic data, leading to suboptimal yields, resource wastage, and reduced profit margins. Current solutions either require expensive hardware (IoT sensors) or are too complex for users with basic digital literacy. The proposed application bridges this gap by providing an offline-capable, AI-driven decision-support system that relies entirely on frictionless user inputs and external dataset integrations.

2

Business Objectives & KPIs

The primary objective is to increase overall farmer profit and productivity through smart, data-driven farming decisions.

KPI 1 — Yield
Increase crop yield by 10% to 20% per planting cycle.
KPI 2 — Cost Reduction
Reduce fertilizer and pesticide costs by 15% through precision AI recommendations.
KPI 3 — Resource Efficiency
Reduce water and resource wastage.
KPI 4 — Profitability
Improve overall farm profit margins by 15% to 20%.
KPI 5 — Financial Assistance
Increase the successful claiming of Central and State government agricultural subsidies by eligible platform users by 25%.
3

Target Users

Primary User: Farmers operating in regions like Mysuru, possessing basic smartphone knowledge and limited reliable internet connectivity.

Note: The "Advisor/Extension Officer" role is explicitly out of scope. The app operates on a direct-to-farmer model.
4

System Scope

In-Scope

  • Farm and field mapping with geographic soil profile fallbacks.
  • Crop cycle tracking (Genetics, Sowing, Harvest).
  • AI-driven prescriptive agronomic advice (Closed-loop ML feedback system).
  • Financial and labor tracking (Cost of Cultivation/ROI calculation).
  • Integration with third-party APIs for weather, market prices, and vendor locations.
  • Offline-first data entry with automated cloud synchronization.

Out-of-Scope

  • Hardware integration (No physical IoT soil/weather sensors).
  • E-commerce and fulfillment (No in-app payment gateways, cart checkout, or shipping logistics).
  • Human Advisor approval workflows.
5

Functional Requirements (FR)

FR1 — Authentication & Onboarding
FR1.1 The system shall authenticate users exclusively via Phone Number and SMS-based One-Time Password (OTP).
FR1.2 The system shall allow users to map a field by dropping a location pin, which automatically fetches regional baseline soil data.
FR2 — Offline-First Data Logging
FR2.1 The system shall allow users to log Field Interventions (chemical applications, irrigation), Harvests, Labor, and Financial Transactions without an active internet connection.
FR2.2 The system shall automatically detect internet restoration and silently sync local data to the central database resolving any timestamps accurately.
FR3 — AI Prescriptive Engine & Alerts
FR3.1 The ML engine shall evaluate weather, soil, and crop genetics to predict threats (e.g., pests, diseases).
FR3.2 The system shall generate specific product recommendations matched against a standardized Agricultural Input Catalog.
FR3.3 The system shall push critical disease/weather alerts directly to the farmer's device.
FR3.4 The system shall trigger an SMS text message fallback for critical alerts if the push notification fails to deliver (e.g., user has mobile data turned off).
FR4 — Vendor & Market Integration
FR4.1 Upon recommending a product, the system shall query a mapping API to display nearby agricultural supply vendors.
FR4.2 The system shall display real-time commodity pricing fetched from Government APIs (e.g., AGMARKNET).
FR4.3 The system shall prompt the user to confirm if they purchased a recommended product and from where, feeding this data back to the ML engine to refine future recommendations.
FR5 — Dynamic Unit Conversion
FR5.1 The UI shall allow data input and output in local/traditional measurement units (e.g., Bigha, Guntha, Quintals).
FR5.2 The backend shall universally convert and store all measurements in standard metric units (e.g., Hectares, Kilograms, Liters) for ML processing and financial calculations.
FR6 — Government Scheme Matching & Notification
FR6.1 The system shall maintain a database of active Central Government (e.g., PM-KISAN, PMFBY) and State Government (e.g., Karnataka's Krishi Bhagya) agricultural schemes.
FR6.2 The backend ML/Rules Engine shall automatically cross-reference the farmer's profile (Farm Region, Area Size, Crop Type planted, and Irrigation Method) against the eligibility criteria of active schemes.
FR6.3 The system shall trigger a Push Notification (and SMS fallback) alerting the farmer when a new scheme becomes available for which they are highly likely to be eligible.
FR6.4 The UI shall provide a simplified summary of the scheme (e.g., "Subsidy for Drip Irrigation") and provide a direct link or phone number to the relevant local government office (e.g., Raitha Samparka Kendra) to claim it.
6

Non-Functional Requirements (NFR)

NFR1 — Usability/UI
The interface must be exceptionally simple, requiring minimal text entry, favoring dropdowns, visual icons, and standardized catalogs.
NFR2 — Localization/i18n
The MVP must fully support English, Kannada, and Hindi. The architecture must utilize localization files to support rapid future language expansion.
NFR3 — Cross-Platform
The application must be deployable natively to both Android and iOS devices from a single codebase (e.g., React Native, Flutter).
NFR4 — Compliance
The system must record explicit user consent (GDPR/Data Privacy standard) before sharing geographic or harvest data with third-party models, tracked via an immutable Audit Log.
7

Core User Stories (Examples)

US1

As a Farmer, I want to log my phone number and receive an OTP, so that I can securely log into my account without remembering a password.

US2

As a Farmer, I want to enter my harvest yield in 'Quintals', so that I don't have to calculate metric conversions in my head.

US3

As a Farmer working in a dead-zone, I want to log my fertilizer application offline, so that my farm records are accurate when I return home to Wi-Fi.

US4

As the ML System, I want to verify if the farmer successfully harvested a crop after following my fungicide recommendation, so that I can increase the confidence score of that product.

US5

As a Farmer in Mysuru with 2 hectares of land, I want the app to notify me if I qualify for the Karnataka Krishi Bhagya rainwater harvesting subsidy, so I can apply for funds before the deadline without having to search through complex government websites.

8

External Integrations Required

Integration Examples / Purpose
SMS Gateway (e.g., Twilio, AWS SNS, MSG91) for OTP and Critical Alert fallbacks.
Weather API (e.g., OpenWeatherMap, IBM Environmental Intelligence) for regional climate telemetry.
Market Price API (e.g., AGMARKNET / Govt Data Portals) for real-time commodity pricing.
Mapping & Places API (e.g., Google Maps API) for field coordinates and nearby vendor location.
Geographic Soil DB (e.g., ISRIC SoilGrids) for zero-input baseline soil profiles.
Government Scheme Data Integration with open government data portals (e.g., data.gov.in) or a curated backend cron-job that scrapes/updates state-level agricultural department announcements.
9

Business Rules & Constraints

BR1 A "Recommendation" is not considered "Applied" until the farmer explicitly logs a matching "Field Intervention."
BR2 E-commerce transactions are strictly prohibited within the app; pricing displayed is advisory based on open-source government data, not a guaranteed vendor quote.
