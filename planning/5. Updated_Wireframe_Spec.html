Screen 10: Crop Cycle Ledger (Profit Margin View)
Associated Workflow: WF-04 (Viewing the outcome of Quick Logs)
Purpose: Calculate and display the exact Cost of Cultivation, Total Income (from harvest), and the resulting Net Profit Margin for a specific planting cycle Entry: Tapping "View Full Ledger" from Home Dashboard OR selecting an active planting from the Fields Dashboard Exit: Back → Dashboard

Interaction & UX Notes for the Ledger
Dynamic Profit Margins: While the crop is still growing (before harvest), the "Profit Margin" will naturally be negative. The UI must clearly label this state as "Current Cost of Cultivation" rather than "Loss," so the farmer understands it is an ongoing investment, not a failure.
Auto-Calculation: Every time a user completes a Quick Log (WF-04) for an expense or harvest, this screen updates instantly in the local database. No internet is required to calculate the profit margin.
4

Responsive Layout Notes

Mobile Phone (Target Device): All layouts are single-column, scrolling vertically.
Form Elements: All input fields and primary buttons span 100% of the screen width (minus a standard 16px padding on left/right) to maximize touch target area.
Orientation: Application is locked to Portrait mode to simplify data entry and prevent map rendering glitches during orientation shifts.
5

Accessibility Considerations

Focus Order: Standard logical DOM order (Top to Bottom, Left to Right).
Keyboard Types: When the user taps 'Area Size', 'Quantity', or 'Phone Number', the OS native numeric keypad MUST trigger. The standard alphabetical keyboard should only ever appear for the "Field Name" input.
Screen Reader Logic: The [+] button in the navigation bar must be explicitly labeled "Log new activity" in the code so screen readers do not just announce "Plus."
6

Developer Notes

Dropdowns vs. Pickers: Any input labeled [ Dropdown ] in this wireframe should be implemented natively as a Bottom-Sheet scrolling picker (like native iOS UIPickerView or Android BottomSheetDialogFragment) rather than an inline HTML <select> style box. This is significantly easier to use one-handed.
Optimistic UI: When the user taps "Save" on the Quick Log or Add Field forms, the app should immediately return to the dashboard and display a success toast, even if the background sync is currently running or paused due to offline status.
