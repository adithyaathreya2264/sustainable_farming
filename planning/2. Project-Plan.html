1

Project Methodology: Unified Flow

Self-Organizing Team

The team owns the collective backlog. Any team member can pull a design, data entry, testing, or coding task based on their current capacity and skill set.

Continuous Flow
Backlog→ In Progress→ Ready for QA→ Done
The Golden Rule of the Flow
Design and Data Preparation tasks must always stay one step ahead of Engineering tasks to prevent developers from being blocked.

Task Dependencies (The Critical Path)

Even without a strict timeline, certain structural realities dictate the order of operations. The team must respect these bottlenecks:

1
UI Before Frontend
A screen cannot be coded (e.g., Task 2.3) until the Figma design (Task 1.2) is finalized.
2
Data Before Logic
The Prescriptive Engine (Task 4.1) cannot be coded until the Rule Matrix (Task 2.5) is documented. The team cannot write algorithms based on guessing.
3
Local DB Before Sync
The Background Sync Queue (Task 2.4) relies entirely on a stable local database schema (Task 1.6).
4

Quality Management & Testing Protocol

Because this is an offline-first agricultural app, standard web testing is insufficient. The team must collaboratively execute this QA script for every major feature:

The "Tunnel" Test
Open the app, start filling out a form, turn on Airplane Mode halfway through. Submit the form. Verify the app does not crash and data saves locally.
The "Reconnection" Test
Turn Airplane Mode off. Wait 10 seconds. Check the Cloud Database to verify the data arrived perfectly.
With the roles, risk management, and strict timelines removed, this blueprint acts purely as a map. Your team can navigate it at whatever speed yields the highest quality code.
