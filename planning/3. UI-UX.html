UI / UX Design Specification

Sustainable Farming App

Date: July 2026
1

Experience Analysis

Primary User Goals

Quickly log field activities, receive instant crop threat alerts, and discover eligible government subsidies.

Cognitive Load & Friction Points

Typing text on mobile keyboards, navigating deep menus, confusion when the internet drops, and calculating metric conversions.

Design Solutions

Zero-Typing Policy: Use large visual cards, bottom-sheet dropdowns, and number pads. Text input is strictly limited to names (e.g., Farm Name).
Omnipresent Offline Reassurance: The user must always know their data is safe, even without a signal.
Localized Mental Models: Inputs use local measurement units (Guntha, Bigha); the UI translates them behind the scenes.
2

Information Architecture (IA)

The app uses a flat, bottom-tab navigation structure. Deep nesting is strictly avoided.

1 Home (Dashboard): Active Alerts, Weather Snippet, Quick Summary.
2 Fields: List of active plantings, Add new field (Map Pin Drop), Harvest logging.
3 [+] Quick Log (Center Action Button): Floating Action Button (FAB) to instantly log an Intervention or Expense.
4 Schemes: Matched government subsidies and application steps.
5 Profile: Language Toggle (EN/KN/HI), Offline Sync Status, Phone Number.
Maximum depth is 3 screens from the home tab.

User Flows

Flow 1: Offline Logging (The Critical Flow)
StartUser taps [+] Quick Log in the field (No internet).
ActionSelects Field → Selects Action (e.g., Fertilizer) → Selects Product → Enters Quantity via numpad (e.g., 2 Bags).
SystemValidates locally.
CompletionSaves to local DB. UI shows a "Saved Offline" toast. Sync icon turns yellow.
Flow 2: Field Mapping & Soil Fetch
StartUser taps Add Field.
ActionMap renders (cached or live). User drags pin to farm location.
SystemReverse geocodes coords against Regional Soil API.
CompletionDisplays baseline soil (e.g., "Clay Loam") and creates the Field profile.

Interaction Design

Bottom Sheets over Modals
For all selections (Crop type, product, units), use bottom sheets that slide up. They are easier to reach with one hand on large phones.
Keyboards
Anytime a quantity or price is required, force the numeric keyboard. Never show the standard QWERTY keyboard for numbers.
Swipe Gestures
Users can swipe right-to-left to dismiss non-critical notifications.
Haptics
Provide a subtle vibration (haptic feedback) when a user successfully logs an offline action, reinforcing that the system "heard" them.
7

Design System

Typography

System native fonts (San Francisco for iOS, Roboto for Android) to ensure perfect rendering of Kannada and Hindi scripts (Noto Sans fallback).

Scale

Large base size (16pt minimum for body text) for readability outdoors.

Color Palette

Primary — Earthy Green#2E7D32
Signifies growth, save actions.
Warning — Alert Red#D32F2F
Used exclusively for ML disease threats.
Info — Muted Blue#1976D2
Used for Government Schemes.
Background — Off-white#F5F5F5
Reduces glare in direct sunlight compared to pure white.
Verification note: Checking the stated palette against the stated background (#F5F5F5) for the WCAG AA text contrast standard this document cites (4.5:1): Primary Green (4.70:1) and Alert Red (4.57:1) pass as text color. Info Blue (4.22:1) falls just short of 4.5:1 as body text on this background, though it passes comfortably (4.60:1) as a button fill with white text. Worth a small adjustment or confirming Info Blue is only ever used as a fill, not as text.

Buttons

Minimum height 48dp (WCAG standard). Full-width at the bottom of the screen for easy thumb access.

Icons

Thick, high-contrast, universally understood icons (e.g., Tractor, Droplet, Rupee/Currency symbol).
8

Responsive Design Strategy

Layout Adaptations: Designed primarily for mobile portrait orientation.
Content Scaling: UI utilizes flexbox; forms and cards span 100% of the screen width minus a 16dp margin.
Typography Scaling: Text sizes adjust based on the device's system accessibility settings (Dynamic Type).
9

UX States

Offline State (Critical)
If no connection, the cloud icon in the header turns Yellow with an "Offline" label. All forms remain fully interactive.
Syncing State
When internet returns, the yellow cloud icon spins and turns Green. A transient toast notification appears: "Data synced to cloud."
Empty State
If no fields are added, the Home dashboard displays an illustration of an empty plot with a large button: "Map Your First Field."
Loading State
Use skeleton loaders instead of spinning wheels for fetching Schemes/Weather to reduce perceived waiting time.
10

Accessibility

Contrast: All text-to-background contrast ratios strictly adhere to WCAG AA standards (4.5:1).
Touch Targets: Minimum 48x48dp for all interactive elements. No closely clustered text links.
Screen Readers: All icon-only buttons (like the [+] FAB) must have hidden semantic labels (e.g., aria-label="Log new activity").
Language Rendering: The UI layout accounts for Kannada and Hindi text expansion (often 20-30% wider/taller than English). UI containers will not use hardcoded heights.
11

Usability Review & Handoff Notes

Pre-Handoff UX Audit Findings

Issue: Originally, selecting a local unit of measurement required typing.
Fix: Changed to a preset scrolling picker (e.g., Guntha, Acre, Hectare) based on the user's GPS region to eliminate typing.
Issue: Map rendering might fail offline.
Fix: The "Add Field" flow uses the device's raw GPS coordinates as a fallback if the map tiles fail to load due to no internet.

Developer Handoff Notes

Strict Metric Backend: The UI MUST display local units (e.g., Bigha), but the frontend code MUST parse this through the conversion matrix and send strictly metric (Hectares) to the backend database.
State Management: Utilize optimistic UI updates. When a user taps "Save" offline, the UI should immediately reflect the save and return to the dashboard, placing the sync payload silently in the background queue.
Localization: Do not hardcode any text strings. Wire everything through standard i18n JSON files from Day 1 to support the MVP's EN/KN/HI requirement.
