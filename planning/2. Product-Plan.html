Product Plan

Sustainable Farming App

Date: July 2026 Phase: Product Planning (Finalized)
1

Product Strategy & Identity

Product Vision
To empower smallholder farmers with accessible, data-driven intelligence for sustainable, resilient, and highly profitable agriculture.
Product Mission
To provide a frictionless, offline-capable mobile platform that bridges the gap between complex agronomic algorithms and daily farming realities, without requiring expensive hardware.
Value Proposition
Precision farming advice, automated government subsidy matching, and farm financial tracking, delivered through a radically simple, offline-first app tailored for the everyday farmer.
Target Users
Smallholder farmers operating in regions like Mysuru, possessing basic smartphone literacy, and facing intermittent internet connectivity.
2

Core Product Principles

Frictionless Input
If a user must type more than a few words, the design has failed. Rely on drop-downs, catalogs, and geolocation.
Offline Resilience
The app must never block a user from recording data because of a dead zone.
Actionable Outputs
Never present raw data without a corresponding recommendation or action step.
Metric-Driven Decisions
The system must capture the economic outcome (ROI) of every agronomic intervention.

MVP Definition

The Minimum Viable Product (MVP) is defined as a decision-support application that allows a farmer to map a field, track a specific planting cycle, record operational expenses/harvests, and receive automated rule-based agronomic alerts and government subsidy matches.

Primary Goal of MVP

Validate that farmers will consistently use the app to log interventions, proving the "closed-loop" data model while providing them immediate value through scheme matching and basic alerts.

Excluded from MVP: Actual Machine Learning (replaced by rule-based logic), advanced debt/insurance tracking, custom lab soil inputs, and mapping third-party vendors.
6

Product Roadmap

Phase 1 The Baseline & The Hook (MVP)
Objective Achieve initial user adoption and establish the data ingestion pipeline.
Key Features Offline-first architecture, Government Scheme matching, Rule-Based alerts, basic operational ledger (income/expense), multi-language UI, SMS fallback.
Exit Criteria: 1,000 active planting cycles logged end-to-end (from sowing to harvest) with a high rate of corresponding intervention logs.
Phase 2 The Intelligence Upgrade (Version 1)
Objective Transition from generic rules to hyper-localized predictive intelligence and complete the financial picture.
Key Features Switch backend to a trained ML Prescriptive Engine, enable Lab Soil Test uploads for dynamic accuracy, introduce Vendor Mapping, and launch Advanced Finance (Loans/Insurance).
Exit Criteria: The ML model achieves a >85% confidence score on successful intervention predictions.
Phase 3 Ecosystem Expansion (Future Release)
Objective Integrate the app directly into the broader agricultural supply chain.
Key Features Automated loan applications via banking APIs based on farm performance data, third-party API access for agricultural researchers, and advanced geospatial management zones (NDVI satellite imagery integration).

Product Risks, Assumptions & Constraints

Risks

Data Reliability The rule-based engine relies heavily on accurate weather and soil APIs. If the external API data is flawed, our recommendations will be harmful.
Subsidy API Volatility Government websites frequently change formats or go offline. Scraping or syncing scheme data may require high backend maintenance.

Assumptions

User Behavior We assume farmers will willingly input their harvest yields and chemical applications if the app is easy to use and provides immediate subsidy alerts.
Connectivity We assume farmers connect to the internet frequently enough (e.g., at least once every 48 hours at home) for the background sync to maintain relevant weather and market data.

Constraints

Technical Constraint The strict offline-first requirement limits the use of real-time server-side validation during data entry; the UI must handle conflict resolution gracefully when syncing.
Scope Constraint No in-app purchasing, e-commerce fulfillment, or payment gateways will be developed.

Decision Log

01
Direct-to-Farmer Model
Excluded the "Advisor" user role. The system will communicate alerts and recommendations directly to the farmer to drastically simplify the permission architecture and UI.
02
Rule-Based MVP Engine
Selected a rule-based agronomic engine over an untrained ML model for the MVP to prevent inaccurate recommendations while silently gathering the ground-truth data needed to train a true ML model for Version 1.
03
Subsidy Prioritization
Promoted Government Scheme matching to the MVP. While it adds engineering scope, it provides the most immediate, tangible financial ROI to the user, acting as the primary acquisition hook.
04
Phased Financial Ledger
Constrained MVP financial tracking to basic operational income and expenses (Cost of Cultivation). Advanced debt, loan, and insurance tracking are deferred to Version 1 to protect the MVP timeline and usability.
